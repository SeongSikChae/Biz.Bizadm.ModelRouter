# 설정 보안정보 암호화 개발 계획

`ServerCertificatePassword`, `OpenAIKey`가 YAML에 평문으로 남는다. `Biz.Bizadm.KMS` + `Biz.Bizadm.KMS.Credentials`(`OsKekCredentialProvider`)로 기동 시 평문이면 암호화해 설정 파일에 다시 쓰고, 암호문(`DEKENC:`)이면 복호화만 해서 런타임에 쓴다. `Configuration`은 Ssl·OpenAI·Kms 중첩 클래스로 나눈다.

- 참고 구현: `DDNSService.Server` `Program.ProtectSecrets`/`WriteConfiguration`, `KmsConfiguration`
- KEK: OS 자격 증명 금고(`biz-bizadm-modelrouter-server://kek` / `default`) 패스워드 + `AesGcmKekManager`(PBKDF2, salt는 설정 `Kms.KekSalt`)
- 범위 밖: KEK/DEK 로테이션, Azure Key Vault, 평문 우회 모드, 새 테스트

## 2. Configuration 중첩 클래스

- 대상: `Configuration.cs` — `Configuration.SslConfiguration`, `Configuration.OpenAIConfiguration`, `Configuration.KmsConfiguration`
- 코드 초안:

```csharp
public SslConfiguration? Ssl { get; set; }
public OpenAIConfiguration OpenAI { get; set; } = null!;
public KmsConfiguration Kms { get; set; } = null!;

public void Validate()
{
    if (Ssl is not null)
        ConfigurationValidator.Validate(Ssl);

    if (OpenAI is null)
        throw new Exception("config field 'OpenAI' must be provided");
    ConfigurationValidator.Validate(OpenAI);

    if (Kms is null)
        throw new Exception("config field 'Kms' must be provided");
    ConfigurationValidator.Validate(Kms);
}
```

- 검증: 빌드
- 선행 단위: 1

## 4. ProtectSecrets

- 대상: `Program.Main`, `Program.ProtectSecrets`, `Program.WriteConfiguration`
- 코드 초안:

```csharp
ConfigurationValidator.Validate(configuration);
ProtectSecrets(configFileInfo, configuration);

// ProtectSecrets
configuration.OpenAI.OpenAIKey = EncryptIfNeeded(configuration.OpenAI.OpenAIKey);
if (ssl?.ServerCertificatePassword is not null)   // UseSsl과 무관하게 평문을 남기지 않는다
    ssl.ServerCertificatePassword = EncryptIfNeeded(ssl.ServerCertificatePassword);
if (rewrite)
    WriteConfiguration(configFileInfo, configuration);
configuration.OpenAI.OpenAIKey = dekCipherService.Decrypt(configuration.OpenAI.OpenAIKey);
```

- 흐름: CredentialStore → `GCM_CREDENTIAL_STORE` → OS 금고 KEK 패스워드 확인(없고 DEK 파일도 없으면 32B 생성·저장, DEK 파일만 있으면 예외) → KekSalt 없으면 16B 생성·저장 → `AesGcmKekManager` → `AesGcmDekCipher(ContentRootPath + DekFilePath)` → `DekCipherService`
- 검증: 실기동 — 첫 기동 시 `DEKENC:` 저장·KekSalt·DEK 파일 생성, 재기동 시 파일 불변
- 선행 단위: 3
